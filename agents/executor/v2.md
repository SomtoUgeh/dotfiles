# Executor 2 on this Mac (cloud first)

As of 26 Oct 2026 the five agents on the Mac and on the julds VM use Executor 2. Executor 1
(`executor`, `executor_cloud`) is no longer configured in them. The VM reaches both through
stdio wrappers with bearer tokens (see `docs/boat-t3-workspace.md`).

| Agent entry | Endpoint | Holds |
|---|---|---|
| `executor_v2` | `https://executor-v2.julds.com/mcp?elicitation_mode=browser` (self-hosted on Cloudflare, fork `julds-ltd/executor-v2`, see its `JULDS.md`) | Everything that can run in the cloud: Notion, Granola, PlanetScale, Postman, Mobbin, Cloudflare (+ Bindings, Builds, Observability, Docs), Figma, Google, PostHog, GitHub, Exa, Context7, OpenAI Docs, Parallel |
| `executor_v2_local` | `http://127.0.0.1:4312/mcp?elicitation_mode=browser` (Mac only) | Only what needs this Mac: Paper, Playwright, 1Password, Aside, Agentation, shadcn, Canva |

Rule: if a service can run in the cloud, it goes in `executor_v2`. Canva is local because
Canva's OAuth only allows its own callback list, which accepts `127.0.0.1` but not
`executor-v2.julds.com`.

## Client setup

```sh
uv run --script scripts/setup_executor_v2.py --check
uv run --script scripts/setup_executor_v2.py --retire-v1   # also removes the v1 entries
```

All five agents connect natively over streamable HTTP and sign in with OAuth on first use:

| Agent | Sign in |
|---|---|
| Claude Code | `/mcp`, pick the entry, Authenticate |
| Grok | `/mcp` in the TUI (headless `grok -p` does not start sign-in) |
| Codex | `codex mcp login executor_v2` and `codex mcp login executor_v2_local` |
| Cursor | `cursor-agent mcp login <name>` (entries present, not signed in yet) |
| OpenCode | `opencode mcp auth <name>` (entries present, not signed in yet) |

Do not use mcp-remote 0.13.5 for Executor 2: Executor returns the RFC 9207 `iss` parameter,
mcp-remote drops it, and its SDK then fails with `IssuerMismatchError`.

The templates carry the same entries: `agents/shared/mcp.json` (inventory),
`agents/opencode/opencode.jsonc` (both), `agents/opencode/opencode.cloud.jsonc` and
`agents/codex/config.toml` (cloud only, since the local endpoint exists only on the Mac).
`sync_agent_config.py` treats `executor_v2_local` like `executor`, so Codex direct defaults
are not re-seeded.

Rollback: the pre-change configs are in
`~/.config/executor-v2-local/v1-agent-config-backup-*`; or rerun `setup_executor.py` to
re-add the v1 entries.

## Local Executor 2 and the stdio bridge

Executor 2 cannot launch processes, so stdio MCP servers sit behind
`scripts/executor_stdio_bridge.mjs`:

- Listens on `127.0.0.1:8930` only. URL: `http://127.0.0.1:8930/<secret>/<server>/mcp`.
  Wrong secret gives 404; any request with an `Origin` header gives 403.
- One long-lived stdio process per server, restarted on the next call if it exits.
- Config `~/.config/executor-v2-local/bridge.json` (0600), secret `bridge.secret` (0600).
  Servers: playwright (npx `@playwright/mcp@latest`), 1password (`/usr/local/bin/1password-mcp`),
  aside (`aside mcp`), agentation, shadcn (`scripts/executor_shadcn.mjs`).
- Node is the fnm `default` alias, which survives Node upgrades.

LaunchAgents (KeepAlive), loaded by `~/.local/bin/executor-v2-local-setup` (run in Terminal;
the Aside sandbox cannot bootstrap LaunchAgents):

| Label | Runs | Log |
|---|---|---|
| `com.julds.executor-v2-local` | `~/.local/share/executor-v2-lab/ev2 serve` (port 4312) | `~/Library/Logs/executor-v2-local.log` |
| `com.julds.executor-stdio-bridge` | the bridge (port 8930) | `~/Library/Logs/executor-stdio-bridge.log` |

Restart: `launchctl kickstart -k gui/$(id -u)/<label>`. Plist sources live in
`~/.config/executor-v2-local/`.

Approvals in local v2: 1Password asks on every call; the others ask only for tools the server
marks destructive.

## Approval rules changed in the cloud

- Exa: `search` and `answer` run without approval (reads; they only cost Exa credits).
- PostHog: `exec` runs without approval for `search`, `info`, `help`, `list` and
  `call <tool>` where the tool name contains get/list/retrieve/search/query/read. Anything
  else asks. An approval policy takes one context object, `({ toolName, toolInput, signal })`,
  and for account-routed apps the command sits at `toolInput.input.command`.

Codex note: `codex exec -s read-only` blocks every Executor call ("requires approval, but
approval policy is never"), because `execute` is not marked read-only. Normal runs use
`danger-full-access` and work.
