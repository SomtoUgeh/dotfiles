# Generating Implementation References

Use this only when the workflow includes generating design images.

## Brief

Capture the product, audience, required sections, real content, primary action, brand constraints, target viewport, and any selected style. Infer routine details from repository context; ask only for decisions that materially change the result.

## Image Set

Choose the smallest set that preserves readable detail:

- one full-page reference for overall rhythm when it remains legible;
- one image per visually distinct section for complex marketing pages;
- focused detail images for dense navigation, tables, forms, or signature interactions.

Generate fresh images at the intended view rather than cropping older composites. Keep repeated chrome and design tokens consistent across the set.

## Art Direction

Choose deliberately among relevant alternatives: centered, split, asymmetric, editorial, product-led, media-led, grid-based, or typographic. Vary section anchors and media placement while maintaining one visual system.

Use real example content. Avoid generated text as the authoritative copy source; preserve user or repository copy in code.

## Acceptance

Before implementation, confirm that the images clearly show hierarchy, spacing, type scale, component boundaries, media treatment, and the primary flow. Regenerate any view whose density, text legibility, or continuity is too weak to guide code.
