# Vectorize API

Use types generated by `wrangler types` for your configured binding. The current API returns asynchronous mutation identifiers; a successful mutation call does not mean the vectors are immediately queryable.

```typescript
const mutation = await env.VECTORIZE.upsert([
  { id: "tenant-a:doc-1", values: vector, namespace: "tenant-a",
    metadata: { key: "tenant-a/doc-1", category: "guide", updated: 1770000000 } },
]);
const result = await env.VECTORIZE.query(vector, {
  namespace: "tenant-a", topK: 5,
  filter: { category: "guide", updated: { $gte: 1760000000 } },
  returnMetadata: "all", returnValues: false,
});
const documents = await env.VECTORIZE.getByIds(["tenant-a:doc-1"]);
const deletion = await env.VECTORIZE.deleteByIds(["tenant-a:doc-1"]);
const details = await env.VECTORIZE.describe();
```

The calling application must authenticate and authorize the tenant before this sequence; do not accept the namespace or IDs as proof of ownership. IDs are unique within an index, so use tenant-qualified IDs even when using namespaces. `insert` does not replace an existing ID; use `upsert` for replacement.

## Query options

- `topK`: at most 100 without returned values/metadata, at most 50 when either is requested.
- `returnMetadata`: `"none"`, `"indexed"`, or `"all"`; use `"all"` when the document key is not metadata-indexed. Boolean values are not the current API.
- `returnValues`: include vectors only when needed.
- `namespace`: restrict candidates to that namespace.
- `filter`: narrow candidates using metadata indexes; namespace selection precedes filtering, and both precede top-K selection.

Filters support documented equality, range, and set operators, for example `{ category: { $in: ["guide", "faq"] } }`. Nested keys can use dot notation. Create appropriate metadata indexes before inserting vectors; consult the metadata reference for supported types and restrictions. A string metadata index uses the first 64 UTF-8 bytes of the indexed value, so avoid collisions in discriminator prefixes.

Record the mutation ID and use `describe()`'s processing information or bounded query checks for visibility. Do not compare differently typed mutation/timestamp fields or assume a fixed 5–10 second SLA. Return pending status or retry within a deadline when the application needs read-after-write behavior.
